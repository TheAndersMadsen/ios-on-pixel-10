# Prior art: how other iOS-userland ports got user sessions, personas and apps (web research, 2026-11-03)

Read by web fetch; claims are the projects' own, not reproduced here.

| Project | Platform | What matters for H3 |
| --- | --- | --- |
| [qemu-t8030](https://github.com/TrungNguyen1909/qemu-t8030) ([issue 49](https://github.com/TrungNguyen1909/qemu-t8030/issues/49), [wiki](https://github.com/TrungNguyen1909/qemu-t8030/wiki/Boot-modes)) | QEMU T8030, iOS 14/15 | Restore once (idevicerestore into emulated NVMe), then boot from NAND without rd=md0: launchd runs every boot task ("Doing boot task: keybag, usermanagerd"); without SEP: "DIAGNOSTICS MODE ENABLED, SKIP INIT". Ramdisk boot (rd=md0) is their restore mode. |
| [eshard iOS 14 on QEMU](https://www.eshard.com/blog/emulating-ios-14-with-qemu-part2) | QEMU T8030, iOS 14 | Normal restored boot; patched datamigrator, MobileKeyBag, SpringBoardFoundation, mobileactivationd; stock apps from /private/var/staged_system_apps copied to /Applications and registered with `uicache -p`. Personas/usermanagerd never mentioned. |
| [ios-sweet](https://github.com/dipa-studio/ios-sweet/blob/main/NOTES.md) | Android phone (Redmi), iOS 16 | Same lineage as this project's SWEET code. From flashed storage with launchd_unsecure_cache=1 all boot tasks run; usermanagerd creates personas 99/199/1000 but cannot save usersession.kb/persona.kb ("Failed to atomically swap ... (45)": HFS has no RENAME_SWAP; their kernel patch 0052 falls back to VNOP_EXCHANGE). Also: ADT /defaults/no-effaceable-storage, a systembag.kb written by their image script, /private/var/containers/{Bundle,Data/System,Shared/SystemGroup,Temp}. |
| [Liter8](https://github.com/Xplo8E/Liter8/pull/15) | real iPhone 11 jailbreak, iOS 27 | No SEP persona: `l8persona` swizzles -[MIAppIdentity resolvePersonaWithError:] to CONTAINER_PERSONA_PRIMARY. Author: "an install-path workaround, not a persona fix". Out of bounds here (fabricates the resolution). |
| [vphone-cli](https://github.com/Lakr233/vphone-cli) ([PR 571](https://github.com/Lakr233/vphone-cli/pull/571)) | Apple Virtualization.framework (PCC research VM), iOS 26 | Real SEPOS in the VM; guests boot "with no system keybag and no effaceable storage" and apps work; passcodes impossible. Its icli registration code is already in docs/REUSE.md item 4. |

Consequence: every working port boots its root as a normal (non-ramdisk) boot, so launchd runs the usermanagerd boot task. This project's own ios26-blazer-r1 QEMU runs with rd=ufsroot0 show boot spec "local", all boot tasks and IN UMD_INIT; every apps-lane run used rd=md0 (boot spec "ramdisk", boot tasks skipped). Expected next problem from ios-sweet: HFS RENAME_SWAP (errno 45, already visible in dirs_cleaner) when usermanagerd saves usersession.kb.
