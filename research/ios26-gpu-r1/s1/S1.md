# M3 S1: the coremem-only GPU init boot (blazer_gpu_tipc=7)

Date: 2026-11-04. Spec: `research/ios26-gpu-native-r1/COREMEM-INIT.md` (agent 1), recipe: `LIVE-EVIDENCE.md` §6 (agent 10).
Evidence labels: SOURCE, HOST, QEMU. **Nothing here is PHYSICAL. The phone has not booted gpu3.** The coordinator runs that boot.

## What changed (SOURCE)

Nested XNU `hk-gpu-m3-s1` **1eb1662** = `hk-gpu-m2-r1` 58f0893 + `bsd/dev/blazer_gpu_tipc.c` (s1/src, sha256 `bde918f5…`) +
new `bsd/dev/hmfw_s1_layout.h` (generated by `tools/fw_layout_s1.c` from the pinned 5940a317 headers). `blazer_gpu.c`, `hmfw_m2_layout.h`,
firmware bytes, the Trusty SEND request and MMU code are unchanged: `blazer_gpu.s1.o` is byte-identical to `blazer_gpu.m2.o` (`ed3c4e85…`).

- **rung 7**: rung 6 plus one store in `gta_shared_init()`, placed after `ui32MarkerVal=1` and before `OS=READY` and the publication barrier:
  `SYSINIT+0x150 = 0x000000E1C013C000` (bytes `00 c0 13 c0 e1 00 00 00`). The raw device VA. The Trusty `fw_va 0xC013C000` and the PA
  `0xBA03C000` stay in SEND only. `_Static_assert`s pin the size 0x3b8, offset 0x150, DMA size 8, raw base, section offset and size, and agreement
  with `blazer_gpu_fwif.h`. `gta_fw_check()` still refuses any other firmware.
- **Readback** (`gta_s1_coremem_check`): after the barrier and before `gta_power_on` and SMC START. Prints the exact `M3 COREMEM:` line plus a
  `forms` line. A mismatch STOPs before power-on.
- **Strict trace gate** (`gta_s1_gate`): runs before HEALTH_CHECK (`M3 S1 boot:`) and after STATEFLAGS_CTRL (`M3 S1 final:`). The trace
  pointer must hold still (20 ms × 25), with no wrap, and log type, size and buffer must match. Entries are parsed from word 0 to the pointer, and each
  must start with a valid id and end within the pointer. It counts MMU fault (EVENT, CORE, CORE_S7), lockup (×3 ids), FAILED_HW_POLL, START_HW_RESET and ASSERT_FAILED,
  plus sysdata `fw_faults`, the assert buffer, HWR flags (HARDWARE_OK set; RESET_IN_PROGRESS, GENERAL_LOCKUP, DM_STALLING, FW_FAULT and RESTART_REQUESTED clear)
  and unacknowledged FWCCB DEBUG_DUMP, CONTEXT_RESET, GPU_RESTART and FW_PF. Any hit, or an invalid trace (`trace_valid 0`), is a FAIL.
  A fault at boot sends **no command**, but the trace and survey are still dumped.
- PASS prints `M2 HEALTH PASS`, then `M3 S1 PASS: clean firmware init and health; no client KICK issued`, and panics with
  `HK GPUTA: rung 7 S1 PASS, boot ended on purpose`. Rung 8 is rung 7's checks with the field left 0. It is a negative control and must not be booted first.
- No client context, CCB, UFO or KICK. The only KCCB commands are M2's HEALTH_CHECK (slot 0) and STATEFLAGS_CTRL (slot 1). `tests/order_check.py` enforces this.

## Host evidence (HOST)

`receipts/host-test.txt` (`tests/run_host.sh`, m1box gcc 16.1.1, ASan+UBSan):
- `tests/test_s1.c`: 612 checks, 0 failed. Covers the exact SYSINIT words for rungs 7 and 8 against COREMEM-INIT §4.3, the LE bytes, and that rung 7 differs from rung 6/8 by the
  field's 4 nonzero bytes only. Also the readback STOP, a clean PASS and a late fault (M2 PASS but S1 FAIL). It has 14 boot-fault models (gpu2-shaped, lockup, poll, reset,
  malformed, truncated, wrapped, empty, moving, assert, fw fault, HWR, DEBUG_DUMP, FW_PF), and each one stops with **0 kicks**. The real gpu2 trace is
  replayed: the 120-word boot slice gives `mmu_fault 2 lockup 1 hwr_reset 1`, and all 476 words give `failed_hw_poll 8`.
- `tests/mutants_s1.sh`: 30/30 caught. `tests/order_check.py` OK. M2's test passes against the S1 source (75), and M2's own test passes with 12/12 mutants.
  The M1 survey test gives 820/0.
- `tools/s1_accept.py` is the coordinator's host acceptance tool and decodes one boot window strictly. On gpu2 relabelled as rung 7 it reports FAIL,
  `mmu_fault 2 lockup 1 failed_hw_poll 8 hwr_reset 1`. `tests/test_s1_accept.py`: 13/13. That covers a synthetic clean PASS, a PASS with the console mirror counted once, and 10 corruptions that FAIL.
  It requires `hwr 0x1 ok` exactly (COREMEM-INIT §5.3).

ARM64 object (`receipts/object-check.txt`, `blazer_gpu_tipc.s1.o.nm.txt`, `gta_s1.dis.txt`): `_gta_s1_coremem`, `_gta_s1_coremem_check` and `_gta_s1_gate`
are present (the scan is inlined into the gate). `gta_shared_init` contains `mov w11,#0xc000; movk w11,#0xc013,lsl#16; mov w12,#0xe1`, the two
`str`s gated on the flag, then OS_READY and `dsb sy`. The gate holds all 11 log ids. The `gta_thread` call order is send_firmware → shared_init →
s1_coremem_check → blazer_gpu_power_on → aoc_smc → gta_m2. The kernel carries the M3 strings. The p1 tree was restored and is clean, and the p1 kernel has 0 M3 strings
(the p1 sha differs before/after only because the build is not bit-reproducible).
